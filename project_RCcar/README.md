# 아두이노 기반  FCA(전방 충돌 방지), 라인추종 기능 탑재 RC카 프로젝트

> **RC카 제작, FCA(전방 충돌 방지) 구현 및 저가형 섀시의 물리적 불균형(RPM Mismatch) 디버깅 분석**

---

## 프로젝트 개요
본 프로젝트는 아두이노(Arduino Uno)와 L298N 모터 드라이버, 초음파 센서, 서보모터, TCRT5000 라인 센서를 활용하여 자율주행 RC카를 구축하고, ADAS 기능 중 하나인 **FCA(전방 충돌 방지 보조)** 및 **단일 센서 기반 라인 탐지 제어**를 구현하기위한 실험 프로젝트입니다.
특히 일반적인 자율주행 RC카는 라인추종을 위해 TCRT5000 센서가 두개 필요하지만, 서보모터와 TRCT5000 센서를 결합하여 1개만으로 라인추종이 가능한 RC카를 만들고자 하였습니다.

프로젝트 진행기간 : 2026-07-23 ~ 2026-07-27

---

### 코드 구조

`project_RCcar.ino`는 다음과 같은 구조로 동작합니다:

1. **`setup()`**: 핀 모드 초기화, 서보모터 중앙 정렬($90^\circ$), 초기 모터 정지
2. **`loop()`**:
   * **1단계 (FCA 장애물 감지):** 초음파 센서로 거리 측정 $\rightarrow$ $5\sim22\text{cm}$ 내 장애물 감지 시 `turnRight()` 실행 ($1200\text{ms}$ 제자리 회전)
   * **2단계 (서보 스캐닝 및 주행):** 장애물이 없으면 서보모터를 좌($10^\circ$)/우($170^\circ$)로 스캔하여 라인 인식 후 주행 방향 결정 (`moveForward()`, `turnLeft()`, `turnRight()`)

## 주요 기능

### 1. FCA (전방 충돌 방지 보조) - **[SUCCESS]**
* 전방 초음파 센서를 통해 임계 거리 5cm~22cm 내 장애물 감지 시 즉시 제동(TCRT 5000 센서를 연결한 전선이 감지될수도 있어서 최소거리 5cm 설정)
* LED 경고등 점등 및 차체 **제자리 회전**을 통해 회피 후 주행 재개 성공

### 2. 전원 및 노이즈 분리 설계 - **[SUCCESS]**
* L298N 전압 강하(-2V) 문제를 해결하기 위해 14500 리튬이온 배터리 기반 전원 보강
* 서보모터 역전압 및 노이즈로 인한 시스템 리셋 방지를 위해 아두이노 전원(보조배터리)과 모터 전원을 완전히 분리 설계

### 3. 라인추종 - **[FAIL]**
* 일반적으로, RC카에서의 라인추종은 TCRT5000 센서 두개를 준비하여 왼쪽의 입력값과 오른쪽의 입력값을 이용
* 하지만 현재 있는 TCRT5000 센서는 하나밖에 없기 때문에, 이를 극복할 방법을 찾다가 서보모터와 라인센서를 결합하여 왼쪽에서의 센서 입력값과 오른쪽에서의 센서 입력값을 이용해 라인추종을 시도
* 다만 하드웨어적 한계때문에 라인추종을 구현하는 것은 실패함

##  진행 중 발생한 문제와 해결책

### 1. LCD 화면 깨짐 및 시스템 강제리셋
* 이슈 : LCD에 이상한 외계어가 출력되거나 아두이노가 자동으로 재시작됨
* 원인 분석 : 서보모터와 DC 모터가 작동할 때 발생하는 역전압 및 전기적 노이즈가 아두이노 전원선으로 역류하여 발생했다고 추정
* 해결 : LCD를 제거하고 아두이노전원과 모터전원을 각각 보조배터리, 건전지로 분리하여 해결

### 2. L298N 모터드라이버 전압 강하 및 모터 파워 부족
* 이슈 : 일반 AA 배터리 4개(1.5V x 4 = 6V)를 넣었을 때 바퀴가 차체를 제대로 밀지 못함
* 원인 분석 : L298N 모터드라이버 내부 회로에서 발생해 모터로 가는 전압을 깎아먹는 전압 강하(-2V) 현상
* 해결 : AA 건전지 대신 규격이 동일한 14500 리튬이온 충전지(3.7V x 2 = 7.4V)를 도입하여 모터 파워를 확보함. 남은 건전지 홀더 2칸은 아두이노 전선을 통해 연결함

### 3. 라인추종과 직진의 불안정성, 하드웨어의 한계
* 이슈 : 바닥 테이프나 일반 바닥에서 차체가 일직선으로 못 가고 좌우로 진동하며 지그재그로 감
* 원인 분석 (다단계 디버깅 과정):
  * 1차 의심 : 서보모터 이동 완충 시간 부족. 해결 : 100ms->280ms로 서보 물리적 회전 시간 확보
  * 2차 의심 : 단일 센서-서보 스캐닝 로직의 시간 지연으로 인한 오버슈팅 현상 의심
  * 3차 의심 : 보조배터리와 연결된 전선 때문에 차체의 무게중심이 오른쪽으로 치우진 것 의심
  * **최종 원인 규명** : 소프트웨어 결함을 배제하기 위해 **센서제어 코드를 완전히 배제하고 `moveForward()`만 실행하는 고정 직진 실험**을 진행함.(`onlystraight.ino`)
  *  * 실험 결과: 소프트웨어 제어가 없는 상태에서도 차체가 일직선을 유지하지 못하고 좌/우로 치우치는 현상 관측.
  *  * **근본 원인 (Root Cause):**
      1. **DC TT 모터의 RPM 불일치:** 초저가 기어드 모터 특성상 동일 전압 입력 대비 좌/우 모터의 내부 기어 마찰력 및 회전수(RPM) 차이
      2. **섀시 구조의 유격:** 아크릴 프레임 조립 조임 유격 및 바퀴 얼라인먼트 미세 오차가 조향에 영향을 미침.
* 해결책 :
  현재 사용한 하드웨어만으로는 근본적인 해결이 어려웠음. 향후에는
  - 모터별 PWM 보정
  - 엔코더 기반 폐루프 제어
  - PID 제어 등
    을 적용하여 개선할 수 있을 것으로 생각됨.

### 그 외
* 서보모터가 회전하기 위해 필요한 delay 시간, FCA 발동 시 차체가 완전히 회전하는데 필요한 delay 시간 등은 직접 코드를 실행시키면서 조금씩 조정함

## 소감 및 느낀점

하드웨어 전원부의 미세한 전압 강하 현상부터 서보모터의 노이즈 처리, 제어 루프 내 시간 지연이 실물 임베디드 시스템에 미치는 영향을 직접 디버깅하며 경험할 수 있었던 의미 있는 프로젝트였습니다.  
특히 지금처럼 모터를 사용할 때에 전압 강하나 개별 모터 출력 편차 등 물리적 고려 요소가 많다는 점을 직접 확인하였습니다.  
비록 원하던 라인추종 기능은 구현하지 못하였지만, 자율주행시스템개론에서 배웠던 FCA 기능은 잘 구현된 것을 확인하여 매우 뿌듯합니다.  
3학년 1학기에 있는 자율주행 SW 설계 과목에서 경주용 자율주행 자동차를 만들어 경주하는 걸로 알고 있는데, 이 경험을 통해 그 과목을 더 잘 진행할 수 있었으면 좋겠습니다.  
또한 이제 군대에 들어가는데, 군대에서도 코딩공부를 손놓지 않아야 겠다고 생각했고, 또한 전역한 뒤에는 STM32를 직접 다뤄서 임베디드 역량을 키울 예정입니다.
